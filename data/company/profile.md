# 架空会社と製品の設定

資料（`data/docs/`）と対応履歴・問い合わせ（管理表）を作るときの前提をまとめたファイル。

- 会社・製品・人物はすべて架空。実在の会社・製品・規約とは関係ない（名前が一致しても偶然）
- このファイルは **RAG の検索対象に入れない**。回答の根拠になるのは `data/docs/` の資料と管理表の対応履歴だけ
- 資料と食い違ったら資料を直すのではなく、まずこのファイルを正として資料をそろえる

## 製品: ハルクロック

ブラウザとスマホアプリで使う勤怠管理サービス。打刻から月次の集計、給与ソフト向けの CSV 出力までを扱う。
給与計算そのものは行わない。

### 機能一覧

| 機能 | 内容 | 使えるプラン（現行） |
| --- | --- | --- |
| 打刻 | Web ブラウザ、スマホアプリ（iOS / Android）、共有タブレットでの打刻。スマホは位置情報の記録を任意で有効にできる | 全プラン |
| IC カード打刻 | 交通系 IC カードを専用リーダーにかざして打刻。リーダーは別売り | スタンダード以上 |
| 勤怠申請 | 打刻修正、残業、休日出勤、休暇（有給・特別休暇）の申請 | 全プラン |
| 承認フロー | 申請の承認。スターターは1段階、スタンダードは2段階、プロは最大3段階 | 全プラン（段数はプランによる） |
| 有給休暇の管理 | 付与日数・残日数の自動計算、年5日の取得状況の一覧 | 全プラン |
| シフト管理 | シフトの作成・公開、希望シフトの提出 | スタンダード以上 |
| 月次の集計と締め | 労働時間・残業・深夜・休日の集計、月次の締め（締め後は管理者だけが修正できる） | 全プラン |
| CSV 出力 | 集計結果を CSV で出力。出力項目と並び順をテンプレートとして保存できる | 全プラン |
| 残業アラート | 月の残業時間が管理者の設定した時間を超えそうなときに、本人と管理者にメールで通知 | スタンダード以上 |
| 複数事業所 | 事業所ごとの就業ルール・締め日の設定 | プロ |
| API | 打刻・集計データの取得用 API | プロ |
| シングルサインオン（SSO） | SAML による SSO | プロ |
| 操作ログ | 管理者の設定変更・データ修正の履歴（1年分） | プロ |

- データの保存期間は契約中ずっと。解約後は 90日で削除する（削除前に CSV で取り出せる）
- 提供していないもの: 給与計算、顔認証打刻、Slack などのチャットツールからの打刻、他社の勤怠システムからのデータ移行ツール。
  資料でも触れない領域として残す（「資料に答えなし」の問い合わせの題材にする）

## 契約条件

| 項目 | 内容 |
| --- | --- |
| 契約の単位 | 会社ごとに1契約。プロ以外は事業所を分けられない |
| 最低契約期間 | 月払いは1か月、年払いは12か月 |
| 支払い方法 | クレジットカード（月払い・年払い）、請求書払い（銀行振込。年払い、または月額 30,000円以上の月払い） |
| 請求のタイミング | 月払いは毎月1日に前月分を請求（ユーザー数が確定してから）。年払いは契約開始日・更新日に12か月分を前払い |
| 支払い期限 | 請求書払いは請求月の末日。クレジットカードはカード会社の締めに従う |
| プランの変更 | 上位プランへの変更は即日。下位プランへの変更は翌月1日から。年払いの途中での下位プランへの変更は次の更新日から |
| 解約の締め日 | 管理画面（設定 > 契約 > 解約の申請）から、**解約する月の前月20日まで**に申請する。その月の末日で解約になる（例: 6月末で解約するなら 5月20日まで） |
| 年払いの途中解約 | 更新日の前日まで契約は続き、残りの月数の返金はしない |
| 自動更新 | 月払いは毎月、年払いは12か月ごとに自動で更新する |
| 解約後のデータ | 解約日から 90日で削除する。削除の前に CSV で取り出せる |

## サポート範囲

### 受付時間とチャネル

| チャネル | 受付時間 | 使えるプラン | 回答の目安 |
| --- | --- | --- | --- |
| チャット（管理画面の右下） | 平日 9:00〜18:00 | 全プラン | 受付時間内なら 30分以内に一次回答 |
| メール | 24時間受付（回答は平日 9:00〜18:00） | 全プラン | 2営業日以内 |
| 電話 | 平日 10:00〜17:00 | スタンダード以上 | その場で回答。調べものは折り返し |

- 休業日: 土日祝、年末年始（12月29日〜1月3日）
- 障害のときは、受付時間外でもステータスページと管理画面のお知らせで状況を案内する。障害の個別の問い合わせは翌営業日に回答する
- 無料トライアル中は、チャットとメールで受け付ける（電話は使えない）

### 対応すること

- 製品の操作方法、設定方法の案内
- 料金・プラン・契約・請求に関する案内（請求書の再発行、支払い方法の変更、プラン変更・解約の手続きの案内）
- 不具合・障害の受付と調査、状況の連絡
- 機能の要望の受付（開発チームに伝える。実装の約束はしない）

### 対応しないこと

人への引き継ぎや、お断りの根拠にする。

- **労務・法令の個別判断はしない**。残業時間の上限や割増賃金の計算方法、有給休暇の付与の要否など、法令の解釈や会社ごとの運用の是非には答えない。社会保険労務士などの専門家への相談を案内する（製品の設定方法としてなら答える）
- **給与計算の代行はしない**。ハルクロックは給与計算を行わず、CSV を給与ソフトに渡すまでが範囲。給与ソフト側の操作も案内しない
- 顧客の代わりに設定やデータ修正を行うこと（初期設定サポートのオプションを除く）
- 他社製品（給与ソフト、会計ソフト、IC カードリーダー以外の機器）の操作方法、他社製品との連携の細部
- 顧客の PC・スマホ・社内ネットワークの環境トラブルの解決（推奨環境の案内まで）
- 従業員本人からの、勤怠データの修正・開示の依頼（契約している会社の管理者を通してもらう）
- 契約者以外への契約情報・請求情報の開示

### 人（リーダー）への引き継ぎが要るもの

ヘルプデスクの担当がその場で答えず、リーダーの佐伯が判断するもの。

- 返金・請求額の減額・支払い期限の延長の依頼
- 料金の個別の値引き、規約に無い契約条件の相談
- 障害による損害の補償の要求、クレーム
- 法令や労務の判断を求める問い合わせ（上記の「対応しないこと」に当たるかの判断を含む）
- 個人情報の開示・削除の依頼、捜査機関などからの照会
- 管理者が退職して誰もログインできないなど、本人確認が要る依頼

### 書き方の癖

対応履歴と問い合わせメモを作るとき、人ごとにこの癖を出す。

**佐伯（丁寧で長い）**

- メモ: 文章で書く。顧客の言葉を「」で引用し、経緯を時系列で残す。会社名・担当者名・連絡先をきちんと埋める
- 回答: 敬語で長め。「お問い合わせありがとうございます。」で始め、結論のあとに理由と手順を番号付きで書き、
  資料の名前（「料金表をご参照ください」など）を添える。条件や例外まで書き足す
- 判断が要るものは自分で答えず、備考に「要確認」「上長確認済み」などと残すことがある
- 料金改定のあとは現行の料金で答える（改定を告知した側なので、古い情報の回答はほぼ無い）

**森下（略語が多く短い）**

- メモ: 体言止めと記号で短く書く。「TEL」「折返し要」「打修」（打刻修正）「有休」「ST」（スタンダード）「PR」（プロ）
  「CSV出」「→」「済」などの略語を使う。担当者名だけで会社名が空のこともある
- 回答: 箇条書きで要点だけ。「管理画面>設定>契約」のように画面の場所を `>` でつなぐ。敬語は最低限
- 電話で答えた内容をそのまま残すので、条件や例外を書き落とすことがある
- 料金改定の前に書いた回答が多く、改定前の料金・プラン名（「ライト」など）のまま残っている行がある

**若林（丁寧だが不慣れ）**

- メモ: 丁寧だが要点がまとまらず、1つのメモに複数の用件が混ざる。誤字・変換ミス（「打国」「有級」など）がある
- 回答: 「〜と思われます」「〜かと存じます」と言い切らない。手順は書くが、プランごとの違いを確かめずに答えることがある
- 古い社内メモや先輩の過去の回答を見て答えるので、改定前の情報（14日のトライアル、初期費用など）が混ざることがある
- 法令に関わる質問にも答えようとしてしまうことがある（本来は佐伯に引き継ぐもの）
